# 0005. Engine user is uid/gid 64999, data under `/srv/<engine>`

- Status: Accepted
- Date: 2026-11-04

## Context

Engine data is bind-mounted from the host, so file ownership is shared between the container and the host. Official images use low ids such as 999. On some provider images that id already belongs to a host user (for example `do-agent` or `systemd-journal` on DigitalOcean), which could then read engine data, secrets and keys.

## Decision

Engine processes run as uid/gid 64999 inside and outside the container (`ContainerSpec::ENGINE_UID`), mapped to the host user `databasify-engine`. Data, configuration, TLS material and logs live under `/srv/<engine>` (mode 755), with `tls/` and `conf/` at mode 750.

## Consequences

- The deploy refuses to continue if the image does not use 64999, or if the uid or gid is already taken on the host by something else.
- When absent, the deploy creates the `databasify-engine` system user and group (no home, no login shell).
- Every engine image must be built with this uid and gid.

## Alternatives considered

- **Keep the upstream ids:** rejected, because of the collisions with host users above.
